실행 방법 및 결과 근거
---------------------
원래 실행 명령:
- python -m pytest -v .\week11\test_load_scores.py
- python -m pytest -v .\week11\test_ai_A.py
- python -m pytest -v .\week11\test_ai_B.py

현재 대화에서 위 테스트들을 다시 실행하려 했으나, Windows Application Control이
.venv의 python.exe와 pytest.exe 실행을 차단했습니다. VS Code 테스트 검색에서도
대상 파일의 테스트가 발견되지 않았습니다. 따라서 아래 A/B 결과는 이번 대화에서
재검증한 값이 아니라 기존 ab_comparison.txt에 기록되어 있던 실행값입니다.
사용자 테스트의 기존 상세 실행 로그는 pytest_results.txt에 있습니다.

빈 줄 동작 확인
--------------
현재 구현은 CSV 행이 비어 있으면 바로 다음 행으로 넘어가므로 skipped에 추가하지 않습니다.
하지만 week11/test_cases.txt는 빈 줄도 건너뛴 이유를 기록해야 한다고 적고,
load_scores.py의 주석은 빈 줄을 기록하지 않는다고 적습니다. 두 문서의 요구가 서로
다르므로 어느 문서를 최종 명세로 볼지에 따라 이 차이의 버그 판정이 달라집니다.

- 사용자 테스트: `len(skipped) == 1`을 요구합니다. 실제 길이는 0이어서 FAIL입니다.
  이는 코드 실행으로 확인된 불일치입니다. test_cases.txt를 기준으로 하면 구현 버그이며,
  load_scores.py 주석을 기준으로 하면 테스트의 기대값이 잘못된 것입니다.
- A 테스트: 점수 목록만 확인하고 skipped를 사용하지 않습니다. 따라서 skipped가 비어 있어도 PASS입니다.
  빈 줄 기록 여부를 검증하지 않습니다. PASS는 이 동작을 정답으로 단언한 결과가 아닙니다.
- B 테스트: 점수 목록만 확인하고 skipped를 무시합니다. 따라서 skipped가 비어 있어도 PASS입니다.
  빈 줄 기록 여부를 검증하지 않습니다. PASS는 이 동작을 정답으로 단언한 결과가 아닙니다.

발견한 문제 및 발견하지 못한 문제
-------------------------------
- 관측된 차이: 사용자 테스트의 빈 줄 사례는 skipped 항목 1개를 기대하지만 실제 구현은 0개를 반환합니다.
  유효 점수 목록 자체는 기대한 값과 일치했습니다. test_cases.txt와 load_scores.py 주석이
  상충하므로 최종 명세가 정해지기 전에는 이를 무조건 구현 버그 또는 테스트 버그라고 단정할 수 없습니다.
- A와 B는 모두 실행에서 PASS했지만, 이것만으로 구현의 모든 동작이 올바르다는 뜻은 아닙니다.
  A와 B의 빈 줄 테스트는 skipped 기록을 확인하지 않아 위 차이를 보고하지 않습니다.
- 사용자 테스트의 XFAIL 사례는 테스트 코드가 `pytest.xfail`을 호출하므로 함수 결과를 검증하지 않았습니다.
  이 실행만으로 헤더만 있는 파일에 대한 구현 동작을 판정할 수 없습니다.
- 사용자 테스트는 잘못된 열 수, 빈 이름/점수, 정수가 아닌 점수를 다루지 않습니다.
- A는 쉼표 포함 이름, 헤더만 있는 파일, 중복 이름을 다루지 않습니다.
- B는 빈 이름/점수, 정수가 아닌 점수, 공백 제거, 헤더만 있는 파일, 중복 이름을 다루지 않습니다.
- 세 묶음 모두 중복 이름 처리 동작은 검증하지 않았습니다.
- 미검사 항목은 이 테스트 실행에서 오류가 관측됐다는 뜻이 아니라, 해당 동작을 확인하는 테스트가 없다는 뜻입니다.
- 이 세 실행에서 실제로 관측된 실패는 사용자 테스트의 빈 줄 기대치 assertion 하나입니다.
  이 assertion이 구현 결함을 나타내는지는 빈 줄 처리에 관한 상충 문서를 정리해야 확정할 수 있습니다.

잘못된 동작을 정답으로 간주했는지
-------------------------------
- A와 B는 빈 줄이 있는 입력에서도 유효 점수가 유지되는지만 검사하고 skipped를 검사하지 않습니다.
  따라서 빈 줄을 기록하지 않는 동작을 명시적으로 정답이라고 단언하지는 않습니다.
- 사용자 테스트는 빈 줄을 skipped에 기록해야 한다고 단언합니다. 이는 test_cases.txt와는 일치하지만
  load_scores.py 주석과는 충돌하므로, 어느 한쪽을 잘못된 동작으로 단정할 수 없습니다.
- 그 외 테스트에서도 구현의 잘못된 동작을 정답으로 간주하는 기대값은 실행 및 파일 내용에서 확인되지 않았습니다.

A와 B의 설계 차이
-----------------
- A는 구현의 구체적인 분기를 따라 공백 제거, 빈 필드, 비정수 점수 등 코드상 처리 경로를 테스트합니다.
  잘못된 열 수와 여러 잘못된 데이터 행은 줄 번호, 원본 행, 이유까지 정확히 비교합니다.
- B는 주어진 명세의 정상·예외·경계 상황을 중심으로 작성했습니다. 따옴표가 있는 쉼표 이름,
  0과 100의 포함 경계, 범위 양쪽 밖 점수에 별도 사례를 둡니다.
- B의 명세에는 건너뛴 정보의 내부 형식이 정해져 있지 않아, 잘못된 열 수와 범위 밖 점수는
  skipped 항목 개수만 확인합니다. A는 코드에서 관찰한 실제 튜플 형식을 그대로 기대값으로 사용합니다.
- 빈 줄 사례에서 두 AI 묶음 모두 유효 점수 보존만 확인해 skipped 기록 여부를 놓쳤습니다.
